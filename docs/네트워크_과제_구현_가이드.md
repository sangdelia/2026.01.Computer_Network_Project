# 네트워크 과제 구현 가이드

## 과제 핵심 목표

이 프로젝트는 **컴퓨터 네트워크** 과목 과제로,  
단순 CRUD 웹앱이 아니라 **네트워크 통신 원리를 실제로 적용**하는 것이 목표다.

구현해야 할 핵심 네트워크 기능:

| 기능 | 프로토콜 | 과제 연관 개념 |
|------|---------|--------------|
| 실시간 반응 갱신 | WebSocket | TCP 기반 양방향 통신 |
| REST API | HTTP/1.1 | 요청/응답 구조, 상태 코드 |
| 인증 토큰 전달 | HTTP Header | 헤더 구조, Bearer 토큰 |
| 페이지 라우팅 | HTTP/2 | 멀티플렉싱, 서버 푸시 |

## 1. WebSocket 실시간 통신 구현

### 왜 WebSocket인가?

```
일반 HTTP 폴링 방식:
  클라이언트 → 서버 (매 1초 요청) → 클라이언트 (응답)
  → 불필요한 트래픽 발생, 지연 존재

WebSocket 방식:
  클라이언트 ↔ 서버 (연결 유지, 이벤트 발생 시 즉시 전송)
  → 단일 TCP 연결 위에서 양방향 실시간 통신
```

### WebSocket 핸드셰이크 과정

```
1. 클라이언트 → 서버: HTTP Upgrade 요청
   GET /ws HTTP/1.1
   Upgrade: websocket
   Connection: Upgrade
   Sec-WebSocket-Key: dGhlIHNhbXBsZQ==

2. 서버 → 클라이언트: 101 Switching Protocols
   HTTP/1.1 101 Switching Protocols
   Upgrade: websocket
   Connection: Upgrade
   Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

3. 이후: TCP 연결 유지, 프레임 단위 양방향 통신
```

### 패키지 설치

```bash
npm install ws
npm install -D @types/ws
```

### WebSocket 서버 구현

Next.js는 기본적으로 WebSocket 서버를 내장하지 않으므로,  
커스텀 서버(`server.ts`)를 만들어야 한다.

**`server.ts`** (프로젝트 루트에 생성):

```typescript
import { createServer } from "http";
import { parse } from "url";
import next from "next";
import { WebSocketServer, WebSocket } from "ws";

const dev = process.env.NODE_ENV !== "production";
const app = next({ dev });
const handle = app.getRequestHandler();

// 룸 관리: opinionId → Set<WebSocket>
const rooms = new Map<number, Set<WebSocket>>();

app.prepare().then(() => {
  const server = createServer((req, res) => {
    const parsedUrl = parse(req.url!, true);
    handle(req, res, parsedUrl);
  });

  const wss = new WebSocketServer({ server, path: "/ws" });

  wss.on("connection", (ws) => {
    let joinedRooms: number[] = [];

    ws.on("message", (data) => {
      const message = JSON.parse(data.toString());

      if (message.event === "room:join") {
        const { opinionId } = message.data;
        if (!rooms.has(opinionId)) rooms.set(opinionId, new Set());
        rooms.get(opinionId)!.add(ws);
        joinedRooms.push(opinionId);
      }

      if (message.event === "room:leave") {
        const { opinionId } = message.data;
        rooms.get(opinionId)?.delete(ws);
      }
    });

    ws.on("close", () => {
      // 연결 종료 시 모든 룸에서 제거
      joinedRooms.forEach((opinionId) => {
        rooms.get(opinionId)?.delete(ws);
      });
    });
  });

  // 다른 API route에서 사용할 수 있도록 broadcast 함수 export
  server.broadcast = (opinionId: number, event: string, data: object) => {
    const room = rooms.get(opinionId);
    if (!room) return;
    const payload = JSON.stringify({ event, data });
    room.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(payload);
      }
    });
  };

  server.listen(3000, () => {
    console.log("> Ready on http://localhost:3000");
  });
});
```

**`package.json`** scripts 수정:

```json
"scripts": {
  "dev": "ts-node server.ts",
  "build": "next build",
  "start": "NODE_ENV=production ts-node server.ts"
}
```

### 클라이언트 WebSocket 연결

**`lib/websocket.ts`**:

```typescript
let ws: WebSocket | null = null;

export function connectWS(token: string) {
  ws = new WebSocket(`ws://localhost:3000/ws?token=${token}`);
  return ws;
}

export function joinRoom(opinionId: number) {
  ws?.send(JSON.stringify({ event: "room:join", data: { opinionId } }));
}

export function leaveRoom(opinionId: number) {
  ws?.send(JSON.stringify({ event: "room:leave", data: { opinionId } }));
}

export function onMessage(handler: (event: string, data: any) => void) {
  ws?.addEventListener("message", (e) => {
    const { event, data } = JSON.parse(e.data);
    handler(event, data);
  });
}
```

**`app/topic/[id]/page.tsx`** 에서 사용:

```typescript
useEffect(() => {
  connectWS("user-token");
  joinRoom(selectedOpinion.id);

  onMessage((event, data) => {
    if (event === "reaction:update" && data.opinionId === selectedOpinion.id) {
      // agreeCount, disagreeCount 상태 갱신
      setSelectedOpinion(prev => ({
        ...prev,
        agreeCount: data.agreeCount,
        disagreeCount: data.disagreeCount,
      }));
    }
    if (event === "comment:new" && data.opinionId === selectedOpinion.id) {
      // 새 댓글 목록에 추가
    }
  });

  return () => leaveRoom(selectedOpinion.id);
}, [selectedOpinion?.id]);
```

## 2. HTTP 통신 원리 적용 포인트

### REST API 설계 (HTTP 메서드 & 상태 코드)

| 작업 | HTTP 메서드 | 엔드포인트 | 성공 응답 코드 |
|------|------------|-----------|--------------|
| 의견 목록 조회 | GET | /api/opinions | 200 OK |
| 의견 작성 | POST | /api/opinions | 201 Created |
| 의견 수정 | PATCH | /api/opinions/:id | 200 OK |
| 의견 삭제 | DELETE | /api/opinions/:id | 200 OK |
| 반응 등록/취소 | POST | /api/opinions/:id/reactions | 200 OK |
| 댓글 작성 | POST | /api/opinions/:id/comments | 201 Created |
| 댓글 삭제 | DELETE | /api/comments/:id | 200 OK |

## 4. 과제 보고서 작성 시 포함할 내용

### 4-1. 사용 프로토콜 분석

- **HTTP/1.1 vs HTTP/2**: Next.js dev 서버는 HTTP/1.1, 프로덕션(Vercel 배포 시)은 HTTP/2 자동 적용
- **TCP 연결 관리**: WebSocket은 HTTP Upgrade 후 TCP 연결을 유지
- **헤더 압축**: HTTP/2의 HPACK 압축으로 반복 헤더 오버헤드 감소

### 4-2. WebSocket vs HTTP Polling 성능 비교

| 항목 | HTTP Polling (1초) | WebSocket |
|------|-------------------|-----------|
| 평균 지연 | 0~1000ms | < 50ms |
| 트래픽 | 요청당 ~800byte | 이벤트당 ~100byte |
| 서버 부하 | 높음 | 낮음 |
| 연결 수 | 매 요청 새 연결 | 단일 연결 유지 |

### 4-3. 보안 고려사항

- HTTPS/WSS 사용 (TLS 암호화)
- JWT 토큰 검증 (WebSocket 연결 시 토큰 파라미터로 인증)
- SQL Injection 방지 (Prepared Statement 사용)
- XSS 방지 (React의 기본 이스케이프 활용)
